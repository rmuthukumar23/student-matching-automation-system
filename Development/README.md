# Development Documentation

This directory contains the project documentation used to plan, design, build, demonstrate, and evaluate the Students for Students tutor-matching application.

## Recommended Reading Order

1. **Criterion_A_Planning.pdf**  
   Problem definition, client context, requirements, and success criteria.

2. **Criterion_B_Design.pdf**  
   Interface, data, and system design decisions made before implementation.

3. **Criterion_B_RecordofTasks.pdf**  
   Development record showing how the project progressed over time.

4. **Criterion_C_Development.pdf**  
   Implementation details and evidence of how the application was built.

5. **Criterion_D.mp4**  
   Demonstration of the finished workflow.

6. **Criterion_E_Evaluation.pdf**  
   Testing, client feedback, success-criteria review, and evaluation of the final solution.

7. **Appendix A.pdf / Appendix B.pdf**  
   Supporting evidence and reference material used during the project.

## What to Look For

If you are reviewing this project from an engineering or product perspective, the most relevant evidence is:

- how the manual tutor-matching problem was translated into requirements
- how administrator needs shaped the interface and workflow
- how Google Sheets was incorporated instead of forcing users into a completely new operational system
- how matching, record updates, and communication were combined into one process
- how the final application was tested against defined success criteria
- how client feedback influenced the design and evaluation

## Note

These documents are retained as historical project artifacts. They reflect the technology, requirements, and constraints of the original IB Computer Science project rather than a currently maintained production system.
